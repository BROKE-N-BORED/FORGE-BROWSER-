# Forge Browser Task List, Review 5 (2026-11-19)

NEW findings only, from the user pass over v0.13 in
REVIEW-2026-11-19.md. The 20 Review 4 items stay on
docs/TASK-LIST-2026-11-17.md and are not duplicated here.
Severity: High breaks a task or misleads, Medium works but
confuses, Low is polish.

- [~] R5-01 (Medium) Clicking Summarize writes the raw protocol
  line 'Forge Browser: ACTION {"type": "summarize"}' into the
  chat log, where it stays in the saved chat history. Fix: run
  the action without echoing the protocol line; log a plain
  "Summarizing the page" line instead. Evidence:
  shots/s06-05-summarize-done.png and the restored chat log in
  later sessions.
- [~] R5-02 (Low) The How to Use dialog has no Close or OK
  button; only the window X or Esc closes it. Fix: add a Close
  button to the dialog. Evidence: shots/s01-04-howto.png.
- [~] R5-03 (Low) How to Use shows developer documentation (the
  repo tree, audit lists, "Verify (the #65 contract)", a
  "Developer topics" section) instead of help written for a
  user. Fix: ship a plain user help text in the dialog and keep
  the developer text out of it. Evidence:
  shots/s01-04-howto.png.
- [~] R5-04 (Low) The navigation toolbar buttons report their
  tooltips as the glyphs themselves ("←", "→", "⟳", "⌂"), so
  hovering never says what a button does in words. Fix: give
  them word tooltips (Back, Forward, Reload, Home). Evidence:
  probe p01 tooltip reads; toolbar visible in
  shots/s02-01-index.png.
- [~] R5-05 (Low) Denying a plan at the gate leaves nothing in
  the chat log, and the turn still ends with a normal "Done"
  answer, so the user cannot see the action was skipped. Fix:
  log a plain line on denial ("You said no, so I did not
  search.") and end the turn as stopped, not done. Evidence:
  shots/s06-04-deny-turn.png and the deny-turn log in the
  review.
- [~] R5-06 (Low) The Vision model picker offers
  nomic-embed-text, an embedding model that cannot describe
  images. Fix: keep embedding models out of the Vision list.
  Evidence: combo inventory in the chat drive (brain and fast
  lists are clean; only the vision list carries it).
- [~] R5-07 (Low) The vault add-entry save crashes with
  AttributeError (app.py save_entry, self._vault is None) if it
  runs while no vault is unlocked. In this review that state
  was reachable only by driving a hidden stacked-page widget;
  no visible-UI path was found. Fix: guard save_entry and the
  other entry actions when no vault is unlocked, with a plain
  message instead of a traceback. Evidence: traceback in
  probe6b.log.
